# Контрольный набор метчинга

`pairs.jsonl` содержит размеченные пары карточки и предложения. В каждой строке есть стабильный `id`, локаль проверяемого текста, часть выборки, исходные тексты, ожидаемые канонические поля обоих объектов и итог сравнения. Допустимые итоги — `Accepted`, `Rejected` и `Uncertain`.

В `expected` перечисляются поля, которые нужно проверить. Путь `measures.dimensions` обозначает размеры в сантиметрах в отсортированном порядке. `measures.length` хранит сантиметры, `measures.volume` миллилитры. Десятичные величины представлены строками. `null` проверяет ожидаемое отсутствие факта. Поле, которого нет в `expected`, пропускается при проверке. Критические различия представлены отдельными парами с похожими заголовками.

Часть `development` используем для корректировки терминов. Для `holdout` подбираем другие формулировки и близкие отрицательные пары. При пополнении реальными поставщиками разделяем данные по товарным семействам и источникам. Такой набор оценивает извлечение параметров и проверку пары. Покрытие кандидатов и качество топ‑3 оцениваем обычным `evaluate` на полном прогоне с размеченными предложениями.

```sh
target/release/sourcematch evaluate-matching --dataset data/matching/pairs.jsonl \
  --split holdout --out runs/matching-base.json
target/release/sourcematch evaluate-matching --dataset data/matching/pairs.jsonl \
  --split holdout --matching-overlay rules/locales/de-es.toml \
  --out runs/matching-de-es.json
```

Отчёт показывает точность итогов по локалям и расхождения по каждому полю. Чтобы проверить исправление, добавьте положительную пару и близкую отрицательную пару, уточните соответствие в наборе терминов, затем повторите оба разбиения. Если поле остаётся неоднозначным, эталонная пара сохраняет статус `Uncertain`.
