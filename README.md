# SourceMatch

SourceMatch помогает команде решить, какие товары стоит закупать для запуска на маркетплейсе в Узбекистане. На входе — карточки товаров, предложения поставщиков и каталог прошлых закупок. На выходе — одна строка на карточку с аналогами, себестоимостью, маржой и рекомендацией «брать», «не брать» или «проверить вручную». Итоговая выгрузка по шаблону задания — [submission.csv](submission.csv).

## Как получается рекомендация

| Шаг | Что происходит |
| --- | --- |
| Поиск фабрики | Локальная модель Qwen сравнивает смысл названий на разных языках. Поиск по словам и признакам дополняет её выдачу. Дополнительный реранкер может пересортировать короткий список по степени сходства |
| Подтверждение аналога | Программа сверяет тип товара, материал, серию, размеры, признаки и количество в наборе. Явные различия исключают предложение. Термины нового поставщика можно добавить к существующему набору и отдельно проверить на размеченных парах |
| Экономика | Программа выбирает самое дешёвое подходящее предложение с допустимой партией. По формулам из задания считает закупку, доставку, пошлину, НДС, комиссии, фулфилмент и маржу. Доставка из Китая считается по большей из сумм за вес и за объём |
| Решение | Правила проверяют наличие аналога, сертификацию, минимальную партию, маржу и спрос. В базовом рынке минимум поставщика должен быть до 1 000 единиц карточки, маржа — от 18%, спрос — от 60 заказов в месяц. Если данных недостаточно, строка показывает, что проверить. Точные денежные поля заполняются при однозначном расчёте |

AI помогает искать предложения и оценивать их сходство. Деньги и допустимость закупки рассчитываются по проверяемым формулам и правилам. Профили риска позволяют получить разные списки для решения человеком. Для каждого можно сравнить вклад в маржу за 30 дней, требуемый капитал, остаток и потери при ухудшении спроса или росте себестоимости. [Сценарии риска и результаты](docs/risk-options.md)

## Данные и проверка качества

- [Исходные материалы](input/) содержат 4 000 карточек, выгрузку поставщиков, исторический каталог, шаблон результата на 3 700 карточек и 300 карточек с ответами заказчика.
- На 300 размеченных карточках проверяем, найден ли нужный аналог в первых трёх предложениях, и считаем штраф за ложные запуски, упущенные позиции и ручные проверки. Эта разметка использовалась при разработке. Качество на второй выгрузке проверяется отдельно.
- [Размеченные пары метчинга](data/matching/) проверяют, распознаются ли материал, размер и другие признаки на разных языках, и получает ли пара правильный статус. Так можно оценивать изменения языковых наборов отдельно от расчёта прибыли.
- Синтетические сценарии дают заранее известные ответы по весу, тарифам, курсу, спросу и марже. Строгая проверка сверяет решение, предложения, суммы и ожидаемые пустые поля.

В [результатах итераций](results/) сохранены прогнозы и отчёты эвалов, альтернативные CSV на 3 700 карточек и сравнение денежных сценариев. Подробности приведены в [отчёте](docs/report.md).

## Воспроизведение локального запуска

Нужны Rust с Cargo и локальный сервер LM Studio. Проверенная конфигурация использовала **LM Studio 0.4.28+2** на Apple Silicon и GGUF-движок **`llama.cpp-mac-arm64-apple-metal-advsimd@2.80.1`**. Сервер слушает **`127.0.0.1:1234`**. В проверенной конфигурации CORS выключен, загрузка по требованию включена. Проект проверяет наличие активных экземпляров перед запросами.

| Настройка | Эмбеддинги | Реранкер |
| --- | --- | --- |
| Модель | Qwen3 Embedding 0.6B | Qwen3 Reranker 0.6B |
| Файл GGUF | `Qwen/Qwen3-Embedding-0.6B-GGUF/Qwen3-Embedding-0.6B-Q8_0.gguf` | `ggml-org/Qwen3-Reranker-0.6B-Q8_0-GGUF/qwen3-reranker-0.6b-q8_0.gguf` |
| Квантование | Q8_0 | Q8_0 |
| Идентификатор в API | `text-embedding-qwen3-embedding-0.6b` | `qwen3-reranker-0.6b` |
| Контекст при загрузке | 2 048 токенов | 4 096 токенов |
| Дополнительные наблюдаемые параметры LM Studio | API показывает контекст | Параллелизм 1, Eval Batch Size 2 048, Physical Batch Size 512, Flash Attention включён, KV-кеш на GPU, Lazy Mode Auto, 32 context checkpoints |
| Подключение из проекта | `/v1/embeddings`, 1 024 числа на вектор, до 32 текстов в пакете | `/v1/chat/completions`, оценки первого токена `yes` и `no`, до 12 кандидатов на карточку |

SHA‑256 проверенных файлов моделей:

- Эмбеддинги — `06507c7b42688469c4e7298b0a1e16deff06caf291cf0a5b278c308249c3e439`.
- Реранкер — `22c9979ce4fbcdc5acdc310c6641c32797eff1aa980b8f7a2db8a8ea23429a48`.

Если модели уже скачаны, выберите указанный GGUF-движок в LM Studio и загрузите их с параметрами из таблицы. Через CLI можно выставить порт, контекст и идентификаторы. Дополнительные параметры реранкера сверяются в настройках загрузки модели. Доля слоёв, перенесённых на GPU, в ответе API не указана. Команды ниже оставляют размещение слоёв на выбор LM Studio. [Загрузка моделей в CLI](https://lmstudio.ai/docs/cli/local-models/load) · [Параметры активных моделей в API](https://lmstudio.ai/docs/developer/rest/list)

В [профиле проекта](profiles/local.toml) задан режим реранжирования `chat_logprobs` и идентификаторы токенов `yes` (9693) и `no` (2152). Для каждой пары программа запрашивает один токен с температурой 0 и отключённым режимом рассуждения.

```sh
lms server start --bind 127.0.0.1 --port 1234
lms load text-embedding-qwen3-embedding-0.6b \
  --identifier text-embedding-qwen3-embedding-0.6b --context-length 2048
lms load qwen3-reranker-0.6b \
  --identifier qwen3-reranker-0.6b --context-length 4096 --parallel 1 \
  --no-speculative-draft-mtp --no-speculative-draft-simple
lms ps
cargo run --locked --release -- prepare --search-profile profiles/local.toml
```

Из корня репозитория выполните одну команду, чтобы получить базовый CSV и финансовую очередь:

```sh
cargo run --locked --release -- run --no-rerank \
  --listings 'input/listings (1).csv' \
  --offers 'input/offers (1).csv' \
  --catalog 'input/ru_catalog (1).csv' \
  --template 'input/submission_template (1).csv' \
  --search-profile profiles/local.toml \
  --scoring-profile profiles/scoring-strict.toml \
  --out submission.csv
```

В базовом режиме используется модель эмбеддингов. На 300 размеченных карточках включение реранкера меняло порядок предложений, сохраняя тот же штраф и попадание правильного аналога в первые три. Для запуска с реранкером уберите `--no-rerank`. Проверить только эмбеддинги можно командой `prepare --no-rerank`. [Прогон с реранкером](results/iteration-02-economics/reranked-evaluation.json)

Для новой выгрузки замените пути к CSV. Исторический каталог и шаблон опциональны. Без шаблона обрабатываются все карточки из выгрузки. Ставки и пороги рынка задаются через `--rules`. При переименовании колонок передайте `--input-profile` со связями имён, например `market_id = "listing_id"` в таблице `[listings]`. Подключение нового набора терминов описано в [эвале метчинга](data/matching/README.md).

В `runs/` сохраняются кеш эмбеддингов, журнал решений и манифесты. Путь к упорядоченной очереди запуска и ручных проверок указан в поле `portfolio` манифеста. Для альтернативных профилей используйте отдельный путь `--out`. [Команды для сравнения профилей](docs/risk-options.md)

## Команды проверки

```sh
cargo test --locked
cargo run --locked --release -- evaluate \
  --predictions results/iteration-04-risk/cautious-labeled.csv \
  --labels 'input/labeled (1).csv'
cargo run --locked --release -- evaluate-matching --dataset data/matching/pairs.jsonl \
  --split holdout --matching-overlay rules/locales/de-es.toml
```

Чтобы проверить полный цикл на искусственных данных:

```sh
set -e
cargo build --locked --release
target/release/sourcematch simulate --seed 42 --out-dir runs/synthetic
for scenario in runs/synthetic/*/; do
  target/release/sourcematch run --no-rerank \
    --listings "${scenario}listings.csv" --offers "${scenario}offers.csv" \
    --rules "${scenario}rules.toml" --out "${scenario}result.csv"
  target/release/sourcematch evaluate --verify-synthetic \
    --predictions "${scenario}result.csv" --labels "${scenario}gold.csv"
done
```
