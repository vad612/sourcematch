# Контекст использования ИИ

Работа велась с Codex на GPT-6. Для поиска использовалась локальная модель Qwen3-Embedding-0.6B через LM Studio. Конвейер подготовлен к попарному реранжированию локальной моделью по профилю проекта. Статус фактических проверок приведён в отчёте.

## Материалы и порядок

1. HTML задания, `input/economics.md` и заголовок шаблона задают ожидаемый результат, формулы и формат.
2. Бизнес-требования, критерии приёмки и рабочие допущения уточняют обработку неполных данных и стоимость ошибок.
3. Архитектура, ADR и `AGENTS.md` задают Rust, локальный инференс, воспроизводимость и правила изменения проекта.
4. Реальные выгрузки и разметка использовались для проверки форматов, поиска примеров ошибок и измерения качества. В модель эмбеддингов передавались ограниченные товарные заголовки через локальный API. Ответы заказчика служили для эвалов.
5. Независимые контрольные расчёты и синтетические изменения условий проверяли пограничные значения и правила принятия решения.

## Проверенные и исправленные предложения ИИ

- Первоначальный парсер обрабатывал числовые интервалы цен, а китайская запись ступени через «от количества» оставалась неопределённой. При разборе диагностических строк добавлена поддержка обеих форм.
- Граница слова при разборе латинских единиц теряла размеры рядом с китайскими иероглифами. Это проявилось на карточках U00110, U00431 и U03340. Проверка границ теперь учитывает соседние письменности.
- Узбекская форма `yig'iladigan` не распознавалась как признак складной модели. Аудит ложного запуска U02272 показал предложение с фиксированной конструкцией. Признак добавлен в проверку совпадений.
- Наличие реранжера среди активных моделей не подтверждало наличие метода реранжирования. Это проверено отдельным запросом к локальному серверу. Отключение реранжирования возможно только явно и отражается в манифесте.

Полная история диалога предоставляется отдельным экспортом из Codex.
