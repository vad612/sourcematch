# Бизнес-требования

## Цель

Компания готовит запуск товаров для дома на маркетплейсе Узбекистана. По каждой карточке ей нужно понять, есть ли подходящее предложение в Китае и стоит ли закупать первую партию. Ошибочный запуск замораживает деньги на несколько месяцев, а ручной поиск и проверка предложения ограничивают число карточек, которые команда может обработать.

В рамках задания бизнес хочет сократить ручную работу на двух этапах: поиске подходящего предложения и оценке целесообразности закупки. Сорсеру в Китае нужны конкретные предложения поставщиков, аналитику — экономика и понятная причина решения. Спорные случаи результат должен выделять для ручной проверки.

## Что получает бизнес по карточке

- До трёх предложений той же модели или явное указание, что аналога нет. Существенны товар, материал, размер, признаки и серия. Цвет не меняет модель. Набор можно собрать из штучного предложения той же модели. Предложения перекупщиков допустимы.
- Себестоимость на складе в Ташкенте и маржу в сумах при текущей цене на площадке. Единица расчёта — то, что покупатель получает по карточке, включая весь набор, если карточка продаёт набор.
- Решение `брать`, `не брать` или `проверить вручную`, уверенность от 0 до 1 и объяснение в одну строку, понятное сорсеру и аналитику. Существенная неопределённость должна быть видна, в том числе когда без веса нельзя уверенно посчитать маржу.

## Экономика и правила решения

Для старта рассчитывается партия в 300 единиц карточки. Если минимум поставщика выше, расчёт ведётся по его минимальной партии. Пригодны для запуска предложения с минимумом не выше 1 000 единиц карточки. Цена берётся со ступени, соответствующей объёму партии. Для расчёта выбирается предложение с самой низкой закупочной ценой за единицу карточки среди аналогов, пригодных для запуска.

В себестоимость входят закупка по курсу 1 780 UZS за юань, доставка из Китая, пошлина по основному материалу и импортный НДС 12%. Доставка считается по большей из двух сумм за вес и объём упаковки. Маржа учитывает текущую цену, комиссию площадки, 3% на невыкуп, себестоимость, фулфилмент и доставку покупателю. Для упаковки ровно 0,6 л применяется диапазон от 0,6 до 5 л, для ровно 5 и 37 л — диапазон от 5 до 37 л. Тарифы и ставки приведены в [правилах экономики](../input/economics.md).

Для решения `брать` должны выполняться все условия. При отказе используется код первого подтверждённого нарушения в указанном порядке.

| Порядок | Условие | Код отказа |
| --- | --- | --- |
| 1 | Есть предложение той же модели | `NO_MATCH` |
| 2 | Товар не относится к категориям, требующим сертификации | `CERT` |
| 3 | Хотя бы одно подходящее предложение доступно с минимумом до 1 000 единиц карточки включительно | `MOQ` |
| 4 | Маржа составляет не меньше 18% от текущей цены | `LOW_MARGIN` |
| 5 | Ожидается не меньше 60 заказов карточки в месяц | `LOW_DEMAND` |

Для решения `брать` используется `OK`. В исходных правилах сертификация нужна для освещения, детских товаров и мелкой техники. Категория для этой проверки определяется по товару.

Спрос считается недостаточным, если единственная оценка или обе оценки ниже порога. При двух оценках по разные стороны порога или при отсутствии обеих спрос требует проверки. Даже если оценки проходят порог, требуется подтверждение в двух случаях. Первый — большая оценка превышает меньшую более чем вдвое. Второй — единственная оценка составляет не меньше 60 и меньше 90 заказов, а у карточки указано менее пяти отзывов. Число отзывов служит признаком для дополнительной проверки прогноза.

Если подтверждённой причины для отказа нет, а одно или несколько условий остаются неподтверждёнными, карточка получает решение `проверить вручную`. В `reason` указывается код первого неподтверждённого условия по тому же порядку. Пояснение называет недостающий факт и действие для проверки. Например, `LOW_DEMAND — оценки спроса по разные стороны порога, уточнить ожидаемое число заказов`.

## Формат результата

Сдаётся `submission.csv` с одной строкой на каждый из 3 700 идентификаторов из [шаблона сдачи](../input/submission_template%20%281%29.csv).

| Поле | Содержание |
| --- | --- |
| `listing_id` | Код карточки из шаблона |
| `offer_ids` | До трёх кодов предложений через `;`. Если выбрано предложение для расчёта, оно идёт первым, остальные — по убыванию уверенности в совпадении. При отсутствии предложения для расчёта все подтверждённые аналоги перечисляются по убыванию уверенности. Если подтверждённых аналогов нет, указывается `NONE` |
| `landed_cost_uzs` | Себестоимость единицы карточки на складе, UZS. Если данных для достоверного расчёта недостаточно, поле пустое |
| `unit_margin_uzs` | Маржа на единицу карточки, UZS. Если данных для достоверного расчёта недостаточно, поле пустое |
| `decision` | `брать`, `не брать` или `проверить вручную` |
| `reason` | Код из правил экономики и пояснение одной строкой. При ручной проверке код указывает, какое условие нужно проверить |
| `confidence` | Уверенность в указанной рекомендации от 0 до 1. Для ручной проверки это уверенность, что требуется проверка |

## Материалы задания

| Материал | Роль |
| --- | --- |
| 4 000 карточек маркетплейса | Товар, текущая цена, характеристики и две внешние оценки заказов |
| 9 704 предложения поставщиков | Модель, цены по объёму партии, минимальная партия, вес и упаковка, если указаны |
| 1 500 позиций российского каталога | История закупок, вес и размеры упаковки известных товаров, связь с предложением при наличии |
| 300 размеченных карточек | Подходящие предложения, эталонные решения и коды причин для проверки |
| Шаблон на 3 700 карточек | Состав и формат сдаваемого результата |

Источник требований — [текст задания](../input/task%20%281%29.html). Условия проверки описаны в [критериях приёмки](acceptance-and-quality.md). Решения по неоднозначным формулировкам обоснованы в [рисках и рабочих допущениях](risks-and-assumptions.md).
