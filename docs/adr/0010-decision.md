# ADR 0010. Решение, неопределённость и объяснение

## Контекст

CSV содержит три решения, а бизнес-правила задают порядок причин. Отказ по подтверждённому условию отличается от ручной проверки по тому же условию.

## Решение

Реализуем чистую функцию над последовательностью `GateOutcome`. Каждый этап возвращает `Pass / Fail / Unknown`, доказательства и возможное действие для проверки. Правила приоритета сосредоточены здесь. [Бизнес-требования](../business-requirements.md)

## Реализация

- Порядок условий: аналог, сертификация, MOQ, маржа, спрос. Если есть подтверждённые нарушения, берём первое из них. Если нарушений нет и все условия пройдены, выдаём `брать` и `OK`. В остальных случаях выдаём `проверить вручную` и код первого неизвестного условия.
- Спрос проверяем по одной доступной оценке или согласным оценкам относительно порога из профиля. При расхождении и при отсутствии обеих оценок условие неизвестно. Категория для сертификации определяется по товару. Когда категория установлена, правило из профиля оценивается отдельно от наличия комиссии. Если её нельзя надёжно определить, условие неизвестно.
- При ручной проверке пояснение называет недостающий факт и следующее действие. Оно собирается из проверяемых значений, ID и коротких шаблонов. Исходный текст продавца в `reason` не переносится.
- `confidence` описывает подтверждённость выданной рекомендации. Стартовая шкала профиля — 0,95 для прямого подтверждения, 0,85 для подтверждённого вывода из согласованных источников, 0,75 при опоре на единственную оценку спроса. Для `брать` берём минимальный уровень среди условий, для отказа — уровень решающего нарушения. Для ручной проверки шкала описывает доказанность необходимости проверки, например известное расхождение источников или неполное совпадение. На разметке проверяем распределение и ошибки по уровням. Стартовая шкала является эвристической.
- `offer_ids` начинается с выбранного для расчёта предложения. Остальные подтверждённые аналоги идут по силе совпадения. Если выбор невозможен, сортируем так весь список. `NONE` ставится при отсутствии подтверждённых вариантов. Причина различает отсутствие аналога и невозможность его уверенно подтвердить.

## Проверка

Таблица тестов включает несколько одновременных нарушений, раннее неизвестное условие и поздний подтверждённый отказ, конфликт спроса, неизвестный аналог и подтверждённое отсутствие аналога. Отдельно проверяются кейс с новой категорией с сертификацией и неизвестной комиссией, а также подходящий товар с неизвестной ценой. Проверяем точные строки решения, коды, ограничения формата и связь первого предложения с рассчитанной экономикой.
