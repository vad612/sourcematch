# ADR 0013. Эвалы по этапам и сравнение версий

## Контекст

Заказчик отдельно оценивает подбор, маржу и итоговое решение. Размечено 300 карточек и часть случаев редкая. Синтетика нужна для границ и известных финансовых ответов.

## Решение

Команда `evaluate` связывает завершённые прогоны из [SQLite](0012-telemetry.md) с реестром тестовых наборов. Основные результаты выдаёт в JSON и таблице по проблемным `listing_id`. Для итоговой оценки использует фиксированную отложенную часть реальной разметки. Связанные карточки по возможности группирует по модели, дубли и связанные предложения проверяет перед делением. Подбор порогов ведётся на отдельной части.

Планируемый вызов для сравнения двух прогонов — `sourcematch evaluate --run runs/candidate --baseline runs/baseline --suite eval/holdout.toml`. Манифест набора хранит список идентификаторов, разметку, тип источника и версию контрольных расчётов.

## Метрики и диагностические разрезы

| Этап | Что измеряем |
| --- | --- |
| Импорт и нормализация | Покрытие существенных полей, частота пропусков, конфликтов и неизвестных единиц по источнику |
| Извлечение и гибридный поиск | Доля карточек с хотя бы одним эталонным совпадением и полнота размеченных аналогов до проверки, по каждому каналу и объединённой выдаче. Отдельно измеряем присутствие самого дешёвого пригодного аналога там, где известен эталон |
| Реранжирование, проверка и итоговые предложения | Изменение позиции эталона на одном наборе кандидатов, попадание эталонного аналога в первые три, доля лишних предложений, верные `NONE` и необоснованные отказы `NO_MATCH`. Разрезы по языку, категории, комплекту и полноте признаков |
| Закупка и экономика | Совпадение выбранного предложения, ступени цены и MOQ с независимыми эталонами, среднее абсолютное отклонение маржи в UZS, доля вычисленных сумм и попадание эталона в рассчитанный диапазон |
| Решения | Суммарная потеря по матрице ТЗ, отдельно ложные запуски, упущенные товары, ручные проверки и коды причин. Потеря считается положительным штрафом, официальный балл — с обратным знаком |
| Быстродействие | Время и стоимость на 1 000 карточек, p95 по этапам и очередям, холодный/тёплый кеш, пиковая память, количество обработанных карточек |

## Сравнение и проверка

- Сравниваем режимы и изменения на одинаковом списке карточек и одинаковых правилах. Отчёт показывает, сколько решений и предложений поменялось, какие карточки ухудшились и как изменилась цена ошибок. Для каждого разреза указываем размер выборки.
- Эффект реранжирования измеряем на тех же кандидатах с включённой и выключенной попарной оценкой. Сверяем число ложных запусков, качество подбора и задержку по карточке.
- Проверяем устойчивость на отложенных товарных семействах. При появлении разметки со второго источника добавляем его как отдельный набор. Для изменений формата используем парные сценарии с теми же карточками. Отдельно показываем строки, где сменились решение, причина или сумма, и подтверждаем ожидаемые причины изменений.
- Результат синтетики выводим отдельно от результата по реальной разметке. Граничные эталоны и важные инварианты служат проверками регрессий. Фиксированные метрики пригодятся для сравнения после первого базового прогона.
- Проверяем эвал на мини-наборе с заранее известной матрицей решений, суммой потерь, попаданием аналога и абсолютной ошибкой маржи. Ожидаемые суммы сверяются с независимыми контрольными расчётами.
