# ADR 0014. Синтетические наборы и финансовые сценарии

## Контекст

Реальная разметка мала и не содержит эталонной маржи. Для устойчивости нужны сценарии, где известны истинные размеры, партия, спрос и исходная себестоимость, а входные CSV специально теряют или искажают часть информации.

## Решение

`simulate` строит воспроизводимые наборы по конфигурации сценария и seed. Для генерации используем `rand_chacha`, для свойств вычислений — `proptest`. Синтетические CSV идут через тот же `run`, а истинные значения остаются отдельной частью набора для `evaluate`. [Генерация с фиксированным seed](https://rust-random.github.io/book/guide-seeding.html), [Proptest](https://proptest-rs.github.io/proptest/intro.html)

Планируемый вызов — `sourcematch simulate --suite scenarios/financial-stress.toml --seed 42 --out-dir runs/stress-42`. Каталог результата содержит входные CSV с правилами сценария, манифест, эталон и результаты сравнения сценариев.

## Наборы

| Набор | Содержание и ожидаемый результат |
| --- | --- |
| Контрольные примеры | Вручную рассчитанные карточки с эталонным аналогом, ценой, партией, маржой и причиной. Границы 0,6/5/37 л, 1 000 единиц, 18% и 60 заказов |
| Синтетическая выгрузка | Сначала создаём истинные товары, комплектации и предложения. Из них формируем разноязычные CSV с пропусками, дублями, искажёнными единицами, близкими неподходящими моделями и конфликтом спроса. Ожидаемые связи строятся из исходных сущностей |
| Парные изменения реального формата | Копия входа и тот же набор с удалённой колонкой спроса, переставленными заголовками, одним конфликтующим ID, новыми формулировками или добавленным дешёвым предложением за пределами тройки поиска. Проверяем ожидаемые изменения и стабильность незатронутых карточек |
| Стресс-сценарии | Начальная сетка меняет курс на ±10% и ±20%, доставку на +15% и спрос на −20%. Дополнительные прогоны меняют комиссии, сертификацию, стоимость закупки и доступность логистики. Шоки курса или тарифа применяются ко всему сценарию, шоки поставщика — ко всем его предложениям |

Фиксируем seed, версию генератора, профиль правил и хеши выгрузок. Для контрольных примеров эталон вычисляется вручную. Для серийных сценариев эталон строим по истинным фактам отдельным эталонным расчётом и сверяем на контрольных случаях. Он не использует модули расчёта и принятия решения проверяемой программы. `proptest` проверяет монотонность затрат, устойчивость к эквивалентной записи единиц и равенство результата при смене порядка обработки.

## Финансовый отчёт

- Для каждого сценария показываем число переходов через порог маржи, штраф по ТЗ, доли ручных проверок и ложных запусков.
- Для выданных решений о закупке рассчитываем сценарный объём вложений как полную стоимость размещённых партий, включая закупочный излишек и доставку. Рост замороженного капитала измеряем по непроданному остатку на заданном горизонте с учётом известного спроса. Отдельно считаем капитал по ложным запускам.
- В отчёте отдельно указываем горизонт, объём продаж, который может быть обеспечен партией, и допущения о возвратах или остатках, если они заданы. Для сетки стрессов показываем чувствительность и худшие сценарии. Квантили используем только для симуляций с явно заданным распределением входов. Сценарные суммы описывают выбранные предположения.

Проверка включает два прогона с одним seed, известные финансовые сценарии, снижение спроса и повышение курса. При неизменном остальном повышение курса уменьшает маржу, а снижение спроса увеличивает непроданный остаток. Результаты по искусственным выгрузкам и реальным карточкам хранятся раздельно.
