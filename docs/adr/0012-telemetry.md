# ADR 0012. Сквозная аналитика прогона

## Контекст

Итоговый CSV не показывает, на каком этапе потерялся верный аналог или откуда взялась неопределённость маржи.

## Решение

Каждый полный прогон сохраняет SQLite через `rusqlite` и JSON-манифест. Одна транзакция на окно содержит исходный порядок карточек, решения, причины и типизированный JSON аудита. Сводки рассчитывают перцентили из наблюдений. [Rusqlite](https://docs.rs/rusqlite/latest/rusqlite/)

| Сущность | Данные |
| --- | --- |
| Манифест | ID и статус прогона, хеши входов, модели, настройки, кеш, счётчики импорта, задержки и хеш CSV |
| Аудит поиска | ID предложений, ранги каналов и реранжера, подтверждённые признаки, причины исключений |
| Аудит экономики | MOQ, ступени и диапазоны цены, выбранное предложение, источники логистики, границы маржи |
| Аудит решения | Состояния условий, решение и объяснение, время этапов |

Денежные величины сохраняются в десятичном виде. В журнале содержатся идентификаторы и причины. Итоговый CSV публикуется после сверки полноты, манифест записывается последним.

## Проверка

Команда `inspect` восстанавливает решение по ID. `evaluate` может прочитать список кандидатов из того же прогона. Сверяем число строк аудита и CSV, распределения причин, хеш и разброс времени обработки.
