# ADR 0012. Сквозная аналитика прогона

## Контекст

Итоговый CSV не показывает, был ли аналог потерян при поиске, отвергнут по признакам, не прошёл расчёт или попал на ручную проверку. Эвалы требуют данных по каждому этапу и возможности воспроизвести конкретный сбой.

## Решение

`tracing` пишет структурированные события и интервалы выполнения. Данные для эвалов сохраняем в локальную SQLite через `rusqlite`. Одна забуференная очередь и один writer группируют вставки в транзакции. `hdrhistogram` агрегирует задержки по этапам. Разрез по карточкам читаем из SQLite. [Tracing](https://docs.rs/tracing/latest/tracing/), [Rusqlite](https://docs.rs/rusqlite/latest/rusqlite/), [HdrHistogram](https://docs.rs/hdrhistogram/latest/hdrhistogram/)

## Схема данных

| Сущность | Данные |
| --- | --- |
| `runs` | `run_id`, статус, хеши входов, идентификаторы и доступные версии обеих моделей, режимы API и профили, сборка, сценарий, хеш результата |
| `stages` | `run_id`, `listing_id` при наличии, этап и номер попытки, ожидание, исполнение, код исхода, кеш-попадание |
| `candidates` | `listing_id`, `offer_id`, номер поискового запроса, позиции каналов, RRF, балл и позиция после реранжирования или причина пропуска, признаки проверки, исход и причина |
| `facts` и `calculations` | Коды пропусков и источники полей, MOQ и ступень, логистика, известные суммы и границы |
| `decisions` | `ordinal`, порядок аналогов, состояние условий, итог, причина, уверенность |

Общие ключи связывают записи в одном прогоне. Денежные значения сохраняем в точном десятичном представлении, агрегаты с деньгами вычисляем в Rust. В журнал пишем коды и ссылки на строки входа, без полного текста продавца. Перечень полей и версию схемы храним рядом с кодом.

## Артефакты и проверка

- Один прогон создаёт SQLite и короткую сводку с покрытием, основаниями отказа, долей ручной проверки, затратами времени и объёмом прогона. Аналитика обязательна, ошибки записи и заполнение очереди видны в статусе.
- После полной записи и проверок публикуется CSV. Манифест с хешем этого файла и статусом успеха публикуется последним. Эвалы читают завершённые прогоны с совпадающими хешами. Неуспешный запуск можно разобрать по статусу и сохранённой диагностике.
- Приёмка включает восстановление пути одной карточки от импорта до решения, сравнение числа итоговых строк и записей аналитики, отсутствие записи со случайным ID, проверку отчёта по задержкам и сценарий остановки writer. Для просмотра предусмотрены SQL-запросы и команда `inspect`.
