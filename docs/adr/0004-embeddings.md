# ADR 0004. Локальные многоязычные эмбеддинги

## Контекст

Нужна работа с названиями на трёх языках и новыми обозначениями без расширения словаря для каждого поставщика. Прогон на защите должен воспроизводиться с фиксированной моделью.

## Решение

Один адаптер к источнику многоязычных эмбеддингов возвращает векторы батчем. Переиспользуем асинхронный клиент `reqwest`. Выбор модели, ожидаемая размерность и формат входа задаются в профиле. Качество на узбекских карточках и сокращениях поставщика измеряем отдельными разрезами.

## Реализация

1. Перед построением индекса проверяем доступность настроенного адаптера и валидный ответ на контрольной паре текстов. Ошибки классифицируются по [контракту воркеров](0011-workers.md).
2. Профиль определяет представление запроса и документа. Название и определяющие признаки имеют приоритет при ограничении длины. Полные структурированные признаки остаются доступны проверке совпадения. Пробелы и отсутствие необязательных полей не добавляют фиктивных признаков. Версия подготовки текста входит в профиль и манифест.
3. Сопоставляем ответы по идентификаторам или индексам запроса. Проверяем полноту и уникальность, конечность чисел, ненулевую норму и размерность каждого вектора. Отдельно различаем ошибку транспорта и ошибку в теле ответа.
4. Кешируем векторы по хешу нормализованного текста, его роли, версии подготовки и подтверждённому отпечатку модели, включая размерность. При неизвестной ревизии переиспользуем кеш только внутри прогона. Перестановка входных строк совместима с кешем. Смена представления вектора требует нового индекса.

## Проверка

Проверяем каждый элемент батча, пустой текст, длинное описание, перестановку результатов, воспроизводимость при разных размерах батча и отбраковку невалидных векторов. Сохраняем задержку запроса, число текстов, усечение и долю кеш-попаданий.
