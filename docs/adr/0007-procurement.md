# ADR 0007. Партия, ступень цены и выбор предложения

## Контекст

MOQ и цена могут быть в штуках или комплектах поставщика. Найденный аналог может оказаться недоступным для стартовой партии.

## Решение

Модуль получает подтверждённые аналоги и сведения о правдоподобных кандидатах, оставшихся неопределёнными. Использует типы количества, проверяемые целочисленные операции и `rust_decimal` для цены. Возвращает состояние MOQ, результаты по предложениям, выбранное предложение при однозначном выборе и возможные варианты при неопределённости. [Правила закупки](../../input/economics.md), [Decimal](https://docs.rs/rust_decimal/latest/rust_decimal/struct.Decimal.html)

## Реализация

1. Сверить, сколько одинаковых предметов в единице карточки и поставщика. Получить минимальный заказ в целых единицах поставщика, достаточный для MOQ и выпуска не менее 300 единиц карточки. Пересчитать MOQ в эквивалент единицы карточки для лимита 1 000 и отдельно сохранить реальное число полных наборов и остаток предметов.
2. Найти ступень по фактическому количеству в единицах поставщика. Проверить включённость границ, незакрытые интервалы и пересечения. При отсутствии однозначной ступени выдать неопределённость с причиной.
3. Нормировать цену на единицу карточки. Учитывать стоимость всего размещённого заказа и отдельно показать остаток, если целые упаковки поставщика создают излишек. Для закупочного сравнения использовать цену одной единицы карточки на применимой ступени. Излишек входит в оценку связанного капитала для симуляции.
4. Для диапазона хранить минимум и максимум. Если верхняя граница одного пригодного предложения не выше нижних границ прочих, выбор однозначен. При пересечении диапазонов или неизвестной цене сохранять все варианты, которые ещё могут оказаться самыми дешёвыми. При равной точной цене выбирать по силе совпадения, затем по `offer_id`. Сравнение охватывает все подтверждённые аналоги, включая предложения вне списка реранжирования и тройки CSV.

## Проверка

Контрольные случаи покрывают MOQ 999, 1 000 и 1 001, пограничную ступень, набор из штучного предложения, кратность заказу, несколько перекупщиков, диапазоны цены, потерю данных об упаковке и дешёвый аналог вне первых трёх. Отказ с `MOQ` подтверждается, когда минимум превышен у всех подходящих предложений и данные не оставляют возможного пригодного варианта.
